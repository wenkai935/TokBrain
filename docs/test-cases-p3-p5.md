## 一、P3 — 状态回写飞书 + 失败重试/人工重投

### TC-P3-01 处理完成回写 work_id 与状态=已归档
- **类型**：正常流 / Event-driven
- **前置**：P1/P2 已落地；飞书表已建「处理状态/work_id/最后修改时间」三列；`dispatch` 中某条 `status=processed` 且带 `work_id`。
- **步骤**：触发 `writeback_feishu_status()` 对已完成条目回写。
- **期望**：飞书对应 record 的「处理状态」=「已归档」、「work_id」=实际 work_id；只更新不新增记录。
- **映射**：需求 P3-1（状态与 work_id 回写）。

### TC-P3-02 failed 条目不自动重投
- **类型**：Unwanted / 安全
- **前置**：某条 `status=failed` 且 `error_code=needs_supplement` 或 `exception`。
- **步骤**：进入新的一轮 `process_queue`，观察该条是否被自动取出重处理。
- **期望**：**不被自动取出**；仅在人工确认后通过重投入口才重入队。
- **映射**：需求 P3-2（失败不自动重投，避免风控期反复撞墙）。

### TC-P3-03 人工重投入口可用
- **类型**：State-driven
- **前置**：存在 `status=failed` 的 record_id。
- **步骤**：调用重投命令 `python bridge_feishu_obsidian.py --retry <record_id>`。
- **期望**：该条 `status` 重置为 `queued` 并重新进入慢轨；日志记录操作人/时间。
- **映射**：需求 P3-2（人工重投路径）。

### TC-P3-04 非终态条目重启续跑
- **类型**：State-driven / 健壮性
- **前置**：进程在 `pending/queued/processing` 状态下被中断（模拟崩溃）。
- **步骤**：重启 `bridge_feishu_obsidian.py`，观察残留非终态条目。
- **期望**：`queued/processing` 被自动接管续跑；`pending` 保持待处理；不产生重复 work（幂等）。
- **映射**：需求 P3-3（重启续跑）。

### TC-P3-05 失败原因可读展示
- **类型**：Unwanted / 可用性
- **前置**：某条处理失败，含 `error_code` 与原始 message。
- **步骤**：读取该条笔记 frontmatter 与飞书状态。
- **期望**：笔记 frontmatter 含 `status=failed` 与 `error` 字段；`error` 含 `error_code` + 人话说明（如「需本地补件：作者未开放下载」），而非原始堆栈。
- **映射**：需求 P3-4（失败可读展示）。注：此用例直接覆盖此前已修复的「笔记 status 停在 pending」缺陷。

### TC-P3-06 回写失败不阻塞主流程
- **类型**：Unwanted / 降级
- **前置**：飞书接口临时不可达（mock 注入 5xx）。
- **步骤**：运行回写逻辑。
- **期望**：主流程（慢轨处理、占位笔记）不受影响；回写失败仅写入本地日志与 `dispatch.error_message`，下一轮重试回写。
- **映射**：需求 P3-1 降级路径。

### TC-P3-07 回写幂等
- **类型**：幂等
- **前置**：同一 `record_id` 已回写一次。
- **步骤**：重复执行回写。
- **期望**：飞书记录值不变、不新增行；本地不产生重复回写记录。
- **映射**：需求 P3-1。

### TC-P3-08 状态枚举校验
- **类型**：边界
- **前置**：`STATUS_OPTIONS = {待处理, 处理中, 已归档, 需补件, 失败}`。
- **步骤**：尝试写入非法枚举值（如「已完成」「error」）。
- **期望**：被拒绝并回退到最近合法态；日志告警。
- **映射**：需求 P3 状态机一致性。

### TC-P3-09 并发回写隔离
- **类型**：并发
- **前置**：多条 `processed` 同时回写。
- **步骤**：并发调用回写（线程/多进程）。
- **期望**：各自 record 独立更新，无交叉串写、无竞态覆盖。
- **映射**：需求 P3-1 并发安全。

### TC-P3-10 空 record_id 不回写
- **类型**：边界
- **前置**：`dispatch` 中存在 `record_id` 为空的本地导入条目（`local-*`）。
- **步骤**：运行回写。
- **期望**：本地条目跳过飞书回写，仅更新本地状态；不抛异常。
- **映射**：需求 P3（本地来源无飞书列）。

### TC-P3-11 回归 — 不影响 P0/P1
- **类型**：回归
- **前置**：P0 硬链接与 P1 双轨已生效（work 2 关键帧 12 张 nlink=2）。
- **步骤**：跑 P3 回写后，检查关键帧硬链接与占位/回填笔记。
- **期望**：硬链接数仍为 2、占用零增长；双轨笔记 frontmatter 状态正确迁移。
- **映射**：回归范围。

## 二、P4 — 入站 API `/inbox/items` + 适配器插槽

### TC-P4-01 正常提交单条 URL
- **类型**：正常流
- **前置**：后端运行；持有合法集成 token。
- **步骤**：`POST /api/integrations/v1/inbox/items`，body `{items:[{link:"https://v.douyin.com/xxx/"}]}` + `rights_attested=true`。
- **期望**：201，返回条目落库（进入 `dispatch` 队列），可在 Obsidian 看到占位笔记。
- **映射**：需求 P4-1（入站 API）。

### TC-P4-02 批量 ≤100 条
- **类型**：正常流 / 边界上限
- **前置**：构造 100 条合法 URL。
- **步骤**：单批提交 100 条。
- **期望**：201，全部入库；响应含计数。
- **映射**：需求 P4（单批 ≤100）。

### TC-P4-03 超 100 条拒绝
- **类型**：边界 / Unwanted
- **前置**：构造 101 条。
- **步骤**：单批提交。
- **期望**：400，提示超出单批上限；**不部分入库**（事务原子）。
- **映射**：需求 P4（单批 ≤100）。

### TC-P4-04 URL 规范化去重
- **类型**：幂等 / 数据质量
- **前置**：`https://v.douyin.com/xxx/` 与 `https://v.douyin.com/xxx/?share=1` 指向同一作品。
- **步骤**：分别提交两条。
- **期望**：归一为同一 `aweme_id`，仅入库一次；返回去重计数。
- **映射**：需求 P4（URL 规范化去重）。

### TC-P4-05 Idempotency-Key 幂等
- **类型**：幂等
- **前置**：带 `Idempotency-Key: k1` 提交一次。
- **步骤**：用同一 key 重复提交。
- **期望**：第二次返回首次结果（200/201），**不重复落库**。
- **映射**：需求 P4（幂等键）。

### TC-P4-06 rights_attested 缺失拒绝
- **类型**：Unwanted / 合规
- **前置**：body 不含 `rights_attested` 或 false。
- **步骤**：提交。
- **期望**：400，明确提示缺少权利声明；拒绝入库。
- **映射**：需求 P4（权利声明强制）。红线第 3 条。

### TC-P4-07 非法 URL 拒绝
- **类型**：边界 / Unwanted
- **前置**：`link` 为非抖音域名或明显无效串。
- **步骤**：提交。
- **期望**：400，标记该条非法；合法条目仍入库（部分合法不整体失败，但非法条目标红）。
- **映射**：需求 P4（校验）。

### TC-P4-08 适配器插槽可扩展
- **类型**：架构 / Optional
- **前置**：现有适配器仅 `douyin_share`。
- **步骤**：新增一个来源适配器（如 `local_text`），注册到插槽，提交该来源数据。
- **期望**：无需改动 API 与流水线即可接入；`source` 字段记录来源。
- **映射**：需求 P4（适配器插槽，面向合法来源）。

### TC-P4-09 认证失败拒绝
- **类型**：Unwanted / 安全
- **前置**：无 token / 错误 token。
- **步骤**：提交。
- **期望**：401，不透露内部错误；审计日志记录来源 IP/时间。
- **映射**：需求 P4（鉴权）。

### TC-P4-10 字段校验（tags 可选、link 必填）
- **类型**：边界
- **前置**：提交不含 `link` 的条目；提交不含 `tags` 的条目。
- **步骤**：分别提交。
- **期望**：缺 `link` → 400；缺 `tags` → 200（默认空标签）。
- **映射**：需求 P4（字段约束）。

### TC-P4-11 并发提交去重
- **类型**：并发
- **前置**：两个并发请求含同一 URL 与不同 idempotency key。
- **步骤**：并发提交。
- **期望**：最终仅一条入库；不出现双记录（数据库唯一约束 + 归一化兜底）。
- **映射**：需求 P4（并发安全）。

### TC-P4-12 回归 — 入站数据走双轨
- **类型**：回归
- **前置**：P1 双轨已生效。
- **步骤**：经 P4 入站一条链接，观察 `dispatch` 与 Obsidian。
- **期望**：秒级占位笔记出现，处理完回填；与飞书来源行为一致。
- **映射**：回归范围。

## 三、P5 — 用户触发式导出工具（书签小工具）

### TC-P5-01 提取当前屏链接
- **类型**：正常流
- **前置**：用户在抖音收藏页加载若干作品，点击书签工具。
- **步骤**：运行书签 JS。
- **期望**：仅收集**当前已加载 DOM** 中的分享链接，输出为清单。
- **映射**：需求 P5（用户触发式，仅当前屏）。

### TC-P5-02 不翻页/不持登录态/不后台常驻（静态断言）
- **类型**：合规 / Unwanted
- **前置**：审查书签源码。
- **步骤**：静态检查 + 行为观察。
- **期望**：源码**不含**自动翻页/scroll 循环、不含 Cookie/登录态读取、不含 `setInterval` 后台常驻；运行即结束。
- **映射**：红线第 1 条；需求 P5（不自动抓取）。

### TC-P5-03 提交到本地 API 成功
- **类型**：正常流
- **前置**：P4 接口可用（127.0.0.1）。
- **步骤**：书签工具把清单 `POST` 到本地 `/inbox/items`。
- **期望**：201，链接进入 `dispatch` 队列并被双轨消费。
- **映射**：需求 P5（提交入站）。

### TC-P5-04 空屏/无链接优雅处理
- **类型**：边界
- **前置**：当前页无作品链接。
- **步骤**：点击书签。
- **期望**：提示「未检测到链接」，不发起请求、不报错。
- **映射**：需求 P5（健壮性）。

### TC-P5-05 跨域提交限制（仅本地）
- **类型**：Unwanted / 安全
- **前置**：书签尝试提交到非 127.0.0.1 地址。
- **步骤**：构造指向外域的请求。
- **期望**：被拦截/拒绝；工具仅允许提交到本地集成端点。
- **映射**：红线第 2 条（不暴露公网）。

### TC-P5-06 适配导出格式（JSON/CSV/文本）
- **类型**：Optional / 兼容
- **前置**：用户另存为 JSON / CSV / 纯文本。
- **步骤**：通过本地转换脚本导入三种格式。
- **期望**：三种格式均能解析为 `InboxItem` 并提交；字段映射正确。
- **映射**：需求 P5（多格式来源）。

### TC-P5-07 不触发任何自动抓取逻辑（合规断言）
- **类型**：合规
- **前置**：集成测试环境。
- **步骤**：运行工具并监控网络请求与后端日志。
- **期望**：**无任何**向抖音服务端发起的翻页/收藏列表遍历请求；仅用户已加载链接被提交。
- **映射**：红线第 1 条（否决自动抓取）。

### TC-P5-08 回归 — 导出数据走双轨正常归档
- **类型**：回归
- **前置**：P0/P1/P2 已生效。
- **步骤**：经 P5 导出一条链接，观察完整归档。
- **期望**：占位笔记秒级出现、关键帧硬链接接入、回填后状态=processed；与现有路径一致。
- **映射**：回归范围。
