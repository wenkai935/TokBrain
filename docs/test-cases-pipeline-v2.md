## 1. P0：关键帧硬链接改造

### 需求追溯（EARS）

- **Ubiquitous**：系统始终应将关键帧以硬链接方式引用到 Vault，不产生第二份磁盘实体。
- **Event-driven**：When 导出作品到 Obsidian，the system shall 为每条入选关键帧在 Vault 附件目录创建指向 `data/keyframes/` 的硬链接。
- **Unwanted**：If 硬链接创建失败（跨卷/文件系统不支持），then the system shall 降级为符号链接，若仍失败则降级为实体复制，并记录降级事件。
- **State-driven**：While 目标硬链接已存在且指向同一 inode，the system shall 跳过创建（幂等）。
- **Optional**：Where 作品被永久删除，the system shall 同步删除 Vault 侧硬链接，避免幽灵占用。

### 用例

| 编号 | 场景 | 前置 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| TC-P0-00 | 硬链接能力探测 | — | 在 `data/` 建临时文件，尝试 `os.link` 到 Vault | 创建成功；`st_ino` 相同；`st_nlink` = 2；磁盘占用只算一份；测试文件被清理 | P0 |
| TC-P0-01 | 单作品导出走硬链接 | D1 已入库并 processed | 执行导出，统计 Vault 附件目录新增文件 | 新增文件数 = 入选关键帧数；每个文件 `nlink` ≥ 2；`data/keyframes` 与 Vault 文件 `st_ino` 一致 | P0 |
| TC-P0-02 | 磁盘占用不翻倍 | 记录改造前占用 | 完成 D1 导出后对比 `data/keyframes` + Vault 附件的**实际**磁盘占用 | 总占用增量 ≈ 0（非 2× 关键帧大小） | P0 |
| TC-P0-03 | 重复导出幂等 | TC-P0-01 已执行 | 对同一 work 再次执行导出 | 不产生新文件、不报「文件已存在」错误；`nlink` 不增长；笔记内容保持一致 | P0 |
| TC-P0-04 | 命名幂等 | — | 用相同 `aweme_id` + 帧序号重复导出 | 目标路径一致，覆盖或跳过由策略决定，绝不产生 `-1.jpg` / `(1).jpg` 类副本 | P0 |
| TC-P0-05 | 入选阈值过滤 | 设置 `KEYFRAME_MIN_SCORE` 为高分值 | 执行导出 | 低于阈值的关键帧不创建链接；笔记中不出现对应 `![[]]` | P1 |
| TC-P0-06 | 源文件缺失 | 手工删除 `data/keyframes/<id>/frame-01.jpg` | 执行导出 | 跳过该帧、记录 warning、不中断整批；其余帧正常导出 | P1 |
| TC-P0-07 | 跨卷降级 | 将 Vault 路径指向另一盘符的测试目录 | 执行导出 | 硬链接失败后降级为符号链接或实体复制；日志明确记录降级原因；导出仍成功 | P1 |
| TC-P0-08 | 作品删除联动 | D1 已导出 | 在 TokBrain 永久删除该作品 | `data/keyframes` 与 Vault 侧硬链接**同时**被清理；磁盘空间真正释放 | P0 |
| TC-P0-09 | 幽灵占用检测 | 手工只删 Vault 侧链接 | 运行占用审计 | 能识别出「data 侧已删、Vault 侧残留」或反之的条目并报告 | P2 |
| TC-P0-10 | 备份去重验证 | — | 用朴素复制 + 7z 备份含硬链接的目录 | 明确记录备份体积翻倍现象；改用 WIM/tar/restic 后体积不翻倍 | P2 |

### 验收标准（P0）

1. 单作品导出后，Vault 附件目录每个关键帧 `nlink` ≥ 2 且 `st_ino` 与源一致。
2. 磁盘总占用增量不超过源文件大小的 5%（余量给文件系统元数据）。
3. 重复导出 3 次，文件数与 `nlink` 均不增长。
4. 作品删除后两侧文件同时消失，磁盘空间释放。
5. 跨卷场景下导出功能不中断，降级路径有日志。

## 2. P1：双轨解耦（占位笔记 + 回填）

### 需求追溯（EARS）

- **Ubiquitous**：系统应保证 Obsidian 归档不依赖 TokBrain 处理完成。
- **Event-driven**：When 飞书表出现新行，the system shall 在 5 秒内写出占位笔记并置 `status=pending`。
- **State-driven**：While 作品处于 `queued`/`processing`，the system shall 保持占位笔记内容不变，仅允许状态字段迁移。
- **Event-driven**：When ingest job 进入终态，the system shall 回填正文与关键帧，并将 `status` 迁移为 `processed`/`needs_supplement`/`failed`。
- **Unwanted**：If 预检失败或触发风控熔断，then the system shall 写 `status=failed` 并附 `error_code`，且不重复自动重投。

### 用例

| 编号 | 场景 | 前置 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| TC-P1-01 | 占位笔记秒级落盘 | D1 新行 | 触发流水线，计时 | ≤ 5 秒内 Vault 出现笔记；frontmatter 含 url / aweme_id / feishu_record_id / tags / status=pending | P0 |
| TC-P1-02 | 不等 TokBrain | D1 新行 | 占位笔记出现后立刻检查 TokBrain job 状态 | 笔记已存在而 job 仍在排队/运行，**两者并行** | P0 |
| TC-P1-03 | 成功回填 | D1 处理完成 | 等待慢轨结束 | 笔记正文被替换为 manifest 内容 + 关键帧片段；`status=processed`；`work_id` 已填 | P0 |
| TC-P1-04 | 回填不新建文件 | TC-P1-03 | 对比回填前后笔记路径与 inode | 路径不变；不产生第二个文件；Vault 无 `-1.md` 副本 | P0 |
| TC-P1-05 | 占位笔记内容完整性 | D1 新行 | 检查占位笔记 frontmatter | 含 `source/url/aweme_id/feishu_record_id/tags/topics/projects/status/work_id/captured_at/tokbrain_synced_at`，且 `projects: []` | P1 |
| TC-P1-06 | 需补件分支 | D2（禁止下载） | 走完整流程 | `status=needs_supplement`；正文保留占位提示与原因；不产生空笔记 | P0 |
| TC-P1-07 | 预检失败分支 | D3（无效链接） | 走完整流程 | `status=failed`；frontmatter 或正文记录 `error_code`；不自动重投 | P0 |
| TC-P1-08 | 幂等：重复 record_id | D4 同链接提交 3 次 | 执行流水线 | 只产生 1 篇笔记；只创建 1 个 work；记录 `duplicated` 而非报错 | P0 |
| TC-P1-09 | 中断续跑 | D5 批量跑一半时杀进程 | 重启流水线 | 非终态条目自动接管；`failed` 条目保持不动等待人工 | P0 |
| TC-P1-10 | 并发写同一笔记 | 两个进程同时处理同一 record_id | 并发触发 | 有文件锁或数据库事务保护；最终笔记内容一致，不出现半截内容 | P1 |
| TC-P1-11 | 队列状态机流转 | D1 | 全程观察 `dispatch.db` 状态 | `pending → queued → processing → processed`，无跳变、无回退 | P1 |
| TC-P1-12 | 风控熔断保护 | 模拟 403/429 | 触发请求 | 熔断生效；30 分钟内不发起新请求；条目状态不误标为 `failed`（应为待重试） | P1 |
| TC-P1-13 | 标签分目录 | D5 含多种标签 | 检查笔记落点 | 按首标签分子目录；无标签落入 `_未分类` | P2 |
| TC-P1-14 | 中文/特殊字符标题 | 标题含 `?*/\|` 等非法字符 | 执行导出 | 文件名被安全化处理；不报 OSError；笔记可被 Obsidian 正常打开 | P2 |

### 验收标准（P1）

1. 新行到占位笔记 ≤ 5 秒，且不依赖 TokBrain 处理完成。
2. 回填后笔记路径与文件数不变，只有内容与 frontmatter 变化。
3. 同一 `record_id` 重复提交 3 次，笔记数与 work 数均为 1。
4. 进程中断重启后，非终态条目自动续跑且无重复产出。
5. `needs_supplement` / `failed` 有明确可读的原因，不产生空笔记。

## 3. P2：飞书加列与增量轮询

### 需求追溯（EARS）

- **Ubiquitous**：系统应仅监听本机、不开放任何入站端口。
- **Event-driven**：When 轮询周期到达（60s），the system shall 查询飞书表「最后修改时间」大于游标的记录。
- **Unwanted**：If 飞书接口返回 401/403，then the system shall 记录认证错误、跳过本轮、不推进游标。
- **Unwanted**：If 本轮处理未完成而下一轮已到，then the system shall 跳过本轮，避免并发重入。
- **State-driven**：While 无新增记录，the system shall 只做一次查询即退出，不调用任何 TokBrain 接口。

### 用例

| 编号 | 场景 | 前置 | 步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| TC-P2-01 | 三列创建成功 | 有表编辑权限 | 创建「处理状态」「work_id」「最后修改时间」 | 三列存在；类型正确；`lark-cli base +field-list` 可见 | P0 |
| TC-P2-02 | 增量过滤生效 | 表内 10 行，游标指向第 6 行 | 执行轮询 | 只返回后 4 行；不返回已处理行 | P0 |
| TC-P2-03 | 无新数据开销 | 游标为最新 | 执行轮询 | 仅 1 次 base 查询；不调用任何 TokBrain 接口；不写库 | P1 |
| TC-P2-04 | 时钟偏差保护 | 飞书侧时间与本机差 3 分钟 | 游标推进后轮询 | 游标回退 5 分钟安全边界生效，不漏行 | P1 |
| TC-P2-05 | 状态回写 | D1 处理完成 | 检查飞书表 | 「处理状态」= 已归档；「work_id」已填 | P1 |
| TC-P2-06 | 认证失效 | 用户 token 过期 | 执行轮询 | 记录认证错误；跳过本轮；**不推进游标**；不误标记录为失败 | P0 |
| TC-P2-07 | 重入保护 | D5 批量，处理耗时 > 60s | 下一轮到达 | 检测到上一轮未结束则跳过；无重复处理 | P0 |
| TC-P2-08 | 降级为全量 | 「最后修改时间」列被误删 | 执行轮询 | 自动降级为全量拉 + `record_id` 差分；功能不受影响；有日志提示 | P1 |
| TC-P2-09 | 延迟实测 | D1 新行 | 记录进入表到占位笔记出现的时间 | ≤ 90 秒（60s 周期 + 处理开销） | P0 |
| TC-P2-10 | 无入站端口 | 常驻运行期间 | `netstat -ano \| grep LISTEN` | 本机无新增监听端口（除 TokBrain 自身 8001/3001） | P0 |
| TC-P2-11 | 限流遵守 | 大量新行 | 观察请求节奏 | 全局并发为 1；每条间隔 4–8 秒；单批 ≤ 100 条 | P1 |
| TC-P2-12 | 长稳运行 | 常驻 24 小时 | 观察内存与日志 | 无内存泄漏；无句柄泄漏；游标单调推进 | P2 |

### 验收标准（P2）

1. 新行进入飞书表到生成占位笔记 ≤ 90 秒。
2. 轮询期间本机不新增任何入站监听端口。
3. 认证失效时游标不推进，数据不丢。
4. 上一轮未结束时下一轮自动跳过，无重复处理。
5. 连续运行 24 小时无泄漏、无崩溃。

## 6. 测试红线

1. **不访问真实抖音**：全部使用人工构造数据或本地授权素材。
2. **不绕过下载权限**：`download_permission=denied` 的作品不得用第三方工具强下，只能走 `needs_supplement`。
3. **不消耗过量 AI 额度**：批量用例（D5）建议控制在 5 条以内，或先关闭真实模型调用做链路验证。
4. **测试环境隔离**：测试数据与现有 2 条真实作品分开，测完清理，不污染 `同步状态.json`。
5. **备份先行**：改造前必须完成数据库与资产的同时间点备份。
