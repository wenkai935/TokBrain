## 二、各资源类型的存储路径与数据来源

### 1. 源媒体文件（原视频/图片）—— `data\source-assets\`

| 子目录 | 生成场景 | 实际示例 |
|--------|----------|----------|
| `item-{import_items.id}` | 本地视频上传入库（`local_upload`）落盘 | `item-4\195022f1fd55470aa60e945032da2fa4.mp4` |
| `work-{works.id}` | 作品**补件上传**（`POST /works/{id}/supplement`） | `work-2\19286be8570e4941a1d0723e0f8d8265.mp4` |

**对应数据库表**：`work_source_assets`

| 字段 | 含义 |
|------|------|
| `path` | 绝对路径（完整含盘符） |
| `sha256` | 文件哈希（幂等/去重依据） |
| `size_bytes` | 字节数 |
| `mime_type` | 类型 |
| `kind` | `video` / `image` |
| `position` | 排序 |

**当前数据**（2026-08-29 实测）：

| work_id | 路径 | 大小 |
|---------|------|------|
| 1 | `item-4\195022f1fd55470aa60e945032da2fa4.mp4` | 199,122,325 B |
| 2 | `work-2\19286be8570e4941a1d0723e0f8d8265.mp4` | 2,782,333 B |
| 3 | `work-3\85a1ea58038146489215ae3539bcf922.mp4` | 5,728,434 B |
| 4 | `work-4\d362162c8c8a4b489b1c05a398b4ffb2.mp4` | 5,020,141 B |

> 本地视频一律落 `item-*`（上传）或 `work-*`（补件），**按 content 头嗅探真实类型**，扩展名由 `_kind_and_extension` 决定（.jpg/.png/.webp/.mov/.mp4）。

### 2. 关键帧图片 —— `data\keyframes\{platform_work_id}\`

**路径规则**（`content_pipeline.py:664`）：`keyframes/{works.platform_work_id}/frame-{序号:02d}-{时间点}.jpg`

| 内容 | 说明 |
|------|------|
| 目录名 | `platform_work_id`（douyin=纯数字作品 ID；local=`local-<sha256>`） |
| 文件名 | `frame-01-0.83s.jpg`（序号-时间秒） |
| 数量 | 每个作品约 12 张（`max_keyframes` 默认 12） |

**对应数据库表**：`keyframes`（`path` 存绝对路径，另有 `ocr_text` / `visual_description` 存分析结果）

**当前数据**：48 张 / 6.1MB（4 个作品 × 12 张）

### 3. 保留媒体目录 —— `data\media\{platform_work_id}`

**定义**：`content_pipeline.py:663` 的 `retained_dir`。已处理作品的媒体副本（当前为空，作品媒体以 source-assets 为准）。

### 4. 临时文件 —— `data\tmp\`

| 文件/目录 | 用途 | 生命周期 |
|-----------|------|----------|
| `keyframes-{work_id}-{uuid}\candidate-*.jpg` | 场景切分候选帧 | 处理完成即清理 |
| `{platform_work_id}.mp4` | 下载的远程视频 | 临时 |
| `{platform_work_id}.subtitle` | 字幕文件 | 临时 |
| `{platform_work_id}.restricted-audio` | 受限音频 | 临时 |

### 5. 调度队列 —— `data\pipeline\dispatch.db`

**bridge_feishu_obsidian.py 专用 SQLite**：飞书多维表格 → Obsidian 的调度队列。
表：`dispatch_items`（状态机 pending→queued→processing→processed/needs_supplement/failed）+ `inbox_idempotency`（入站幂等）。

### 6. 日志 —— `data\logs\`

- `f2-*.log`：抖音 F2 链路日志（爬取/解析）

## 三、前端如何访问本地资源

前端不直接读磁盘，全部通过后端 HTTP 接口（`127.0.0.1:8001`）：

| 资源 | 前端取值 | 后端接口 |
|------|----------|----------|
| 封面 | `work.cover_url` → `localAssetUrl()` | `GET /api/library/works/{id}/cover` |
| 相关图片 | `asset.url` → `resolvedAssetUrl()` | `GET /api/library/works/{id}/assets/{name}` |
| 关键帧 | `track_report` / 详情数据 | （经后端分析后写回） |

`frontend/lib/assets.ts` 规则：
- `localAssetUrl(v)`：`v` 以 `/api/` 开头 → 拼接 `API_BASE`；否则返回 `null`（不可用）
- `resolvedAssetUrl(v)`：`/api/` 开头拼接 base；否则原样返回（可能是远程 URL）

## 四、资源与数据库的关联矩阵

```
works.platform_work_id
  ├── keyframes/{platform_work_id}/      → keyframes 表 path 字段
  └── media/{platform_work_id}/          → 保留媒体

works.id
  ├── work_source_assets.path            → data/source-assets/{item-N | work-N}/...
  ├── work_summaries.asset_ids           → summary 引用的资产名（经 /assets/{name} 访问）
  ├── knowledge_chunks.text              → 纯文本（无文件）
  └── usage_events                       → 用量记录（无文件）
```

## 五、跨盘/硬链接注意事项

- **Obsidian 导出**（bridge_feishu_obsidian.py P0）：关键帧可硬链接到 Obsidian 仓库（同 NTFS 卷时 `os.link` 成功，`nlink=2` 只占一份空间；跨盘降级 junction/实体复制）。
- **删除作品**（前端"永久删除"）：会删除 `work_source_assets.path` 指向的文件 + 关联 chunks/keyframes/summary + 数据库行；若文件同时被 Obsidian 硬链接引用，需两侧同步删除避免幽灵占用。
