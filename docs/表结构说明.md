# TokBrain 数据库字段说明文档

> 数据库文件：`data/douyin_rag.db`（SQLite，WAL）
> 生成时间：2026-08-29 ｜ **结构校订：2026-10-30（对应 schema v11 / 应用 v1.0.0）**
> 数据规模（2026-10-30 实测）：works **14** 条 / knowledge_chunks **305** 条 / keyframes **149** 条 / usage_events **291** 条 / jobs **44** 条 / import_items **403** 条 / chunk_vec **305** 条向量

> 结构版本以 `app/services/migrations.py` 的 `SCHEMA_VERSION` 为准（当前 **11**），数据库内 `app_settings` 的 `schema` 键同时记录该值。表清单以 `app/models.py` 为准；任何离线检查请用只读方式打开（`mode=ro`），避免误创建空库。

## 11. `chunk_vec` — sqlite-vec 向量虚表

向量检索不是"预留"，已经在用。表由 `sqlite-vec` 扩展创建，随 `knowledge_chunks` 同步维护。

| 对象 | 类型 | 说明 |
|---|---|---|
| `chunk_vec` | vec0 虚表 | 主表，字段为 chunk 主键 + 1024 维向量（百炼 `text-embedding-v4`） |
| `chunk_vec_rowids` / `chunk_vec_chunks` / `chunk_vec_vector_chunks00` / `chunk_vec_metadatachunks00` | shadow 表 | 由扩展内部维护，**不要手工写入或删除** |
| `chunk_vec_info` | 普通表 | 扩展写入的元信息 |

使用方式与注意事项：

- 建表、写入、KNN 查询都在 `app/services/vector_store.py` 内完成；启动时会重建索引并校验维度。
- 直接用普通 `sqlite3` 命令行查 `chunk_vec` 会报 `no such module: vec0`——这是**没有加载扩展**，不代表表不存在或索引没建。需要校验时读 `chunk_vec_rowids` 的行数即可（当前 305，与 `knowledge_chunks` 一致）。
- 向量不可用（扩展加载失败）时，检索会自动降级为词法匹配，不阻断检索。
- 作品永久删除时，对应向量按 `work_id` 一并清理。

## 12. 独立队列库 `data/pipeline/dispatch.db`

不在主库里，是桥接链路的独立 SQLite 文件：

| 项 | 说明 |
|---|---|
| 路径 | `data/pipeline/dispatch.db` |
| 用途 | 飞书→TokBrain 入站任务的分发队列与状态机（pending / queued / processing / processed / needs_supplement / failed） |
| 写入方 | `POST /api/integrations/v1/inbox/items` 只入队；真正处理由常驻的 `bridge_feishu_obsidian.py --watch` 完成 |
| 注意 | `data/dispatch.db`（0 字节）是历史遗留空文件，不是队列，不要误读 |

## 关键关联关系

```
works 1 ── 1 work_summaries (work_id 唯一)
works 1 ── n work_source_assets
works 1 ── n knowledge_chunks
knowledge_chunks 1 ── 1 chunk_vec (向量，按 chunk 主键对齐)
works 1 ── n keyframes
works 1 ── n usage_events
works n ── n collections (collection_memberships)
works.lid ── 1 dispatch.db 队列行 / 1 飞书表行 / 1 Obsidian 笔记
import_batches 1 ── n import_items
import_items n ── 1 works (existing_work_id)
jobs 1 ── n import_batches
```
