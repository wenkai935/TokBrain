## 1. 一句话结论

你手上其实是**三个物理上分开、逻辑上已半连通的系统**：小七源码+运行拷贝（`D:/code/xiaoqi`）、生产主目录（`D:/agent`，含 Hermes 与认证中心）、视频知识库（`D:/code/TokBrain-main`）。它们早已在 **Hermes 这层**用 MCP 串起来（家居工具 + 知识检索/控制），所以"合并"不是重新连线，而是**把两套运行时、两台机器，收敛成一个大脑、一个库、两类出口**——前提是先补上飞书入口这条被遗漏的链路，否则阶段 3 会把它掐断。

## 3. 真实运行架构（四层，别把代码目录当成部署拓扑）

```
[音箱] 小爱 LX06 + client-rust 补丁
   │  WS :4399（音频/回采/run_shell）
   ▼
[NAS 192.168.10.104] xiaoqi-bridge（Docker，host 网络）
   │  :4400 音乐桥（已部署，2首歌）  :8000 小智WS  :8003 OTA
   ▼
[小智] xiaozhi-esp32-server（Docker）→ LLM provider = hermes_voice（受限版）
   │  HTTP :8642
   ▼
[Hermes] systemd 原生进程（不是容器！）
   ├─ hermes-gateway-7320d9b7 :8642  语音网关
   ├─ hermes-household        :9119  dashboard
   └─ HERMES_HOME=/vol1/1000/hermes-state
        ├─ 家居工具 home_mcp → HA :8123（192.168.10.107）
        ├─ tokbrain 只读 MCP（5工具）→ NAS SQLite 快照
```

## 5. 整合规划

### 5.1 目标形态

**一个 Hermes 大脑 + 一个库 + 两类出口**，共享同一身份/审计边界（`xiaoqi-auth`）：

- 家居出口：灯/空调/制冰机/电视 → HA 反代 + 统一认证
- 知识出口：硬件PM/职业/面试知识 → 带时间戳溯源；保留 `evidence_state` 证据边界（没证据不进问答，防幻觉）

### 5.2 四阶段路线（每阶段独立验收，不中断现有服务）

| 阶段 | 内容 | 风险 | 验收 |
|---|---|---|---|
| 1 音箱问答 | **不加 SOUL 规则**，只验证 MCP `INSTRUCTIONS` 生效 | 零，不碰库 | ✅ 2026-11-23 已通过：调 `tokbrain_search`、答出带时间戳条目 |
| 2 写入闭环 | 语音收藏/加合集走 control MCP；飞书新增入库是两段式+人工闸 | 低，但**须先备份库** | 语音加收藏→库里增行→网页可见 |
| 3 收敛 NAS | **3a** 迁只读检索问答到 NAS（可行）；**3b** 飞书写入桥另议 | 中，**原方案会掐断飞书入口** | 关掉 Windows 后语音问答仍可用（基于快照） |
| 4 共进程共库 | 检索/写入嵌进 Hermes 进程，取消 MCP 跨进程边界 | 最高，最后做 | 单进程同时提供家居+知识 |

### 5.3 阶段 3 的关键修正（2026-11-22 审查发现）

飞书入口链路依赖 **Windows 本机**：lark-cli 扫码授权（token 3h/refresh 7d）+ playwright 真实 Chrome 桌面会话（**纯 SSH 环境不行**）。所以：

- **只迁 FastAPI 到 NAS 会直接断掉"飞书表格→知识库"整个入口**，原规划写"关掉 Windows 全链路可用"是错的。
- 3b 的产品取舍二选一：① 保留一台 Windows 常驻机专做飞书入口；② 改造成飞书官方 API + 无头浏览器 + 授权持久化后迁 NAS（改动大，涉及平台风控）。**需你定**。
- NAS 的库是 scp 快照（chmod 400 只读），不是实时主库；阶段 4 前接受"刚加的还没进快照"的延迟。

### 5.4 边界（明确不做什么）

- 本地 stdio MCP 启动保持环境变量——MCP 规范推荐，强改成票据反而违规。
- 语音"认人"不动——fail-closed 证据校验是设计选择，不是漏洞。
- 飞书自动解析不跳过人工确认闸——防自动烧额度/撞风控（遇 423/429 熔断 30 分钟）。

## 6. 踩坑点

**环境坑**：Hermes 是 systemd 不是 Docker；`docker ps` 查不到。音乐桥 LX06 真机出声未验证（README 只在 OH2P 验证过）。解析通道 2026-11-02 起改浏览器，需桌面会话。

**配置坑**：两处 `config.py` 唤醒词曾不一致（旧拷贝"你好小七"，NAS 实际"大肥鱼"）；以 NAS 当前配置为准。NAS 配置"本地产脚本→审阅→同步"，别直接改。

**使用坑**：`tb_batch_confirm` 不触发入库，必须再 `tb_library_ingest`；飞书新增默认不下载，要 `download=true` + 人工 `tb_sync_confirm`；agent 读不到飞书表内容，别让它自调 `tb_import_links`。

**维护坑**：`D:/agent` 改文件前先看 `AGENTS.md`/`.workbuddy/memory`；别的会话曾覆盖过改动。源码仓库本体无硬编码密钥，但 `TokBrain-main` 的 `.cmd`/`.env.bak` 有明文飞书/control token，开源前须轮换。
