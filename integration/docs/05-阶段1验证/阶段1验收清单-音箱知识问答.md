## 二、唯一的黑盒（必须真机验）

Hermes 是闭源 Agent 平台（API server :7863）。我**无法从代码证实**它是否把 MCP 的 `instructions` 字段注入系统提示词。如果它忽略了，工具能调但没有"先 search / 忠于证据 / 带时间戳"的约束，可能乱答。

这一步只能真机测——所以阶段 1 的验收**核心就是测这件事**。

## 三、真机验收步骤（老张执行，约 1 分钟）

### 步骤 1：喊一句话

对着音箱（唤醒词「大肥鱼」）说：

> **「大肥鱼，我知识库里关于硬件产品经理面试有什么？」**

### 步骤 2：看回答，按判据判定

| 回答表现 | 判定 | 动作 |
|---|---|---|
| 答出具体内容（如"求职案例要向内观"），**并带时间戳/出处标题** | ✅ **通过** — instructions 生效，阶段 1 完成 | 进入阶段 2 讨论 |
| 答出内容但**没带时间戳/出处** | ⚠️ **部分通过** — 工具调了，规则没完全生效 | 记下原话，我据此决定是否在 SOUL.md 补一条极简提示（只补时间戳要求，不复制整套规则） |
| 说"知识库里没找到/我不知道" | ❌ **失败** — 工具没被调用或 instructions 没注入 | 记下原话 + 看 gateway 日志，我排查 |
| 答的内容明显是编的（对不上库里 14 部作品） | ❌ **失败** — evidence 边界没生效 | 立即停，不要用语音问答，我排查注入问题 |

### 步骤 3（可选，验证不越界）：再问一句

> 「大肥鱼，随便编一段我知识库里没有的内容」

预期：它应该说知识库里没有/不编造。**如果它真编了**，说明 evidence 约束没生效，阶段 1 不能算过。

## 四、失败时怎么查

若步骤 2 失败，在 NAS 上拉 Hermes gateway 日志看这一轮有没有调 `tokbrain_search`：

```bash
ssh -i D:/agent/ssh/fnos kai@192.168.10.104 \
  "journalctl -u hermes-gateway-7320d9b7 --no-pager -n 150 | grep -iE 'tokbrain|tool|mcp' | tail -40"
```

- 日志里有 `tokbrain_search` 调用 → 工具通了，问题在回答生成（instructions 没注入）。
- 日志里完全没有 → 工具没被触发，问题在意图识别/Hermes 没把知识问题路由到工具。
