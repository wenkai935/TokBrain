# 框架整合：审计 + 最小骨架

> 2026-11-23。用 ponytail-audit 的 Lean 原则审视两个项目的**框架层**（MCP 框架、认证、配置、规则），
> 再做"框架整合"。整合 = 删重复、收边界，**不是造新框架**。
> 本轮只读审计 + 本地设计；**未改生产、未改 D:/agent 运行配置、未动 NAS**。

## What this repo does（审计对象）

审计对象不是业务代码，是两个项目"框架层"如何拼在一起：小七（`D:/agent`，Hermes systemd + 4 个本地 MCP）和 TokBrain（`D:/code/TokBrain-main`，两套 MCP + 飞书桥）。假定负载：单家庭、单用户、2-5 语音终端、7×24——**不是多租户**。

## 审计发现

### Must fix

**1. 认证体系两张皮：全局模型里没有 TokBrain**
（`D:/agent/xiaoqi-auth/config.example.json:22-71`；`D:/code/TokBrain-main/mcp_server/_http_guard.py:22`）
- **What this is:** xiaoqi-auth 注册表有 8 个 client / 6 个 aud，覆盖音乐桥/HA/电视/小智/命令/文件，**零 tokbrain**；TokBrain control 自带 BearerGuard + `TOKBRAIN_CONTROL_TOKEN`，独立一套。
- **Problem:** "统一认证中心"漏了知识库这一半。同一个 Hermes 调家居走票据、调知识库走另一套 token，账本分家；不能统一吊销、统一审计。
- **Fix:** 在注册表加 `tokbrain-control` aud + `kb:read/kb:ingest` scope + 一个 `hermes-knowledge` client；auth_server 的 scope 映射加 `kb: → tokbrain-control`（`auth_server.py:100-102`）。control 侧 BearerGuard **保留**（见 #3），本阶段只让身份账本统一。
- **If skip it:** 知识库永远是认证体系的盲区；阶段 4 共库时要返工。

**2. 问答规则写两遍，会漂移**
（`D:/code/TokBrain-main/mcp_server/tokbrain_hermes_stdio.py:27-36`；`TokBrain与Agent融合规划-20261122.md:80`）
- **What this is:** stdio MCP 的 `INSTRUCTIONS` 已写完整问答规则（先 search、默认 limit 3、最多三次调用、忠于 evidence、带时间戳）。但融合规划阶段 1 又说"在 SOUL.md 加一段问答规则"。
- **Problem:** 两处规则会不一致——MCP 工具描述改了，SOUL.md 没改，Hermes 行为取决于谁先被读到。SOUL.md 是全局人设，塞工具细节违反"单一事实源"。
- **Fix:** **删掉**往 SOUL.md 加问答规则的计划。规则只在 MCP `INSTRUCTIONS` 一处（它本来就生效——Hermes 加载 MCP 时自动携带）。规划阶段 1 改为"验证现有 INSTRUCTIONS 生效"。
- **If skip it:** 阶段 1 白改一次 SOUL.md，还制造第二个规则源。

### Should fix

**3. 两套 MCP 框架不合并——这是决策，不是缺陷**
（stdio `tokbrain_hermes_stdio.py` 298 行手写 JSON-RPC；control `mcp_control.py` 821 行 FastMCP）
- **What this is:** 只读用 stdio（零依赖、只读 SQLite），控制用 HTTP（FastMCP + 33 工具）。传输、职责、部署位置（NAS vs Windows）都不同。
- **Problem:** 看着像"重复的 MCP 框架"，但合并会把零依赖的只读适配器拖进 FastMCP 依赖，且跨机调用链改变。
- **Fix:** 不合并。框架整合只在**配置/身份/契约层**统一，传输层各留各的。
- **If skip it:** 无——这是明确的不做事决策，防止过度整合。

**4. 飞书 table token 明文在仓库里**
（`D:/code/TokBrain-main/launchers/启动飞书同步.cmd:9-10`；`mcp_server/control.env.bak-20261117-233552`）
- 已在飞书链路审查 §5 记录；整合时必须确认 TokBrain 若要开源，这些进轮换清单。本轮不改。

### Nice to have

**5. 无——其余是风格，不报。**

## Verdict

框架层的病不在"缺功能"，在"边界没收拢"：两个 must fix 都是**重复/遗漏**问题，修法是删和补，不是加层。

`Lean: -0 lines, +0 dependencies`——框架整合阶段不新增依赖、不新建框架；净代码变化是"删掉一处重复计划 + 注册表加几条声明"。

`Not checked:` 未跑任何代码、未连 NAS 写、未碰飞书/抖音；未读 TokBrain 的 `app/` 业务实现（本轮只审框架层）。

## 整合骨架（本轮产出）

### 目标：一个边界，三类统一，传输层不动

```
统一前                              统一后（框架层）
─────────────────────────────────   ─────────────────────────────────
Hermes → 家居：xiaoqi-auth 票据       Hermes → 所有资源：xiaoqi-auth 票据
Hermes → 知识：TOKBRAIN_CONTROL_TOKEN （知识库纳入注册表，账本统一）
问答规则：MCP INSTRUCTIONS + SOUL.md 问答规则：只 MCP INSTRUCTIONS（删 SOUL 那份）
MCP 框架：stdio(读) + HTTP(写)        MCP 框架：不变（职责不同，不合并）
```

### 三个具体动作

1. **注册表补 TokBrain**（`D:/agent/xiaoqi-auth/config.example.json`）
   - `aud` 加 `tokbrain-control`
   - `scope` 加 `kb:read`（只读检索）、`kb:ingest`（入库/确认）
   - `client` 加 `hermes-knowledge`，只给 `kb:*`——最小权限
   - `auth_server.py:100-102` 映射加 `"kb:": "tokbrain-control"`

2. **删重复规则**
   - 融合规划阶段 1 的"SOUL.md 加问答规则"删除，改为验证 MCP `INSTRUCTIONS`。
   - SOUL.md 保持现状（已有"知识库是可检索资料"的分寸，够了）。

3. **写一份框架契约**（本文即为契约），定义唯一事实源：
   - 身份/权限 → xiaoqi-auth 注册表
   - 知识问答规则 → TokBrain stdio MCP 的 INSTRUCTIONS
   - MCP 挂载 → `hermes/live/config.yaml`
   - 飞书入口 → Windows 桥（阶段 3b 前不变）

### 明确不做（防止过度整合）

- 不把 stdio 适配器改成 FastMCP（会引入依赖、破坏零依赖只读）。
- 不让 control 侧现在就换票据（BearerGuard 已工作；换它要动 Windows 服务，属阶段 3b/4）。
- 不碰 SOUL.md 现有内容、不动数据库、不动飞书表。

### 5. 收僵尸授权：`tv-helper`（本轮新增）

删电视助手时只清了代码，**认证注册表还留着它的完整授权**——`tv-helper` aud + `tv:power/tv:key/tv:read` 三个 scope + `hermes-home` 上的对应授权。而 8765 从未监听、服务根本不存在。这是典型的"删了服务、忘了收钥匙"。

| 清掉的内容 | 位置 |
|---|---|
| `tv-helper` aud 声明 | `_audience_清单` |
| `tv:power` `tv:key` `tv:read` scope 声明 | `_scope_清单` |
| `hermes-home` 的 3 个 `tv:*` scope + `tv-helper` aud | `clients.hermes-home` |
| `"tv:": "tv-helper"` 前缀映射 | `auth_server.py` `prefix_to_aud` |
| 测试里的 TV 票断言与夹具 | `test_auth.py` |

**效果**：`hermes-home` 请求 `tv-helper` aud 现在返回 `401 该 client 无权访问此 aud`。攻击面少一个 aud、少 3 个 scope。

### 6. 修配置契约缺口（本轮新增）

真实 `config.json` 与模板 `config.example.json` 有 4 处 scope 不一致：`hermes-home` 和 `life-agent` 各缺 `ha:media:write`、`ha:notify:write`。这是批次 A 改模板时没回填真实配置留下的——**部署批次 A 时播报/解静音会因 scope 收窄而 401**。

已补齐，现在模板与生产零差异。批次 A 部署不再需要先动配置。
