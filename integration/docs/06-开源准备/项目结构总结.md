# 小七（Open-XiaoAI）项目结构总结

> 用于开源前的结构梳理与 README 认知基础。生成于 2026-11-22。

## 一、项目是什么

小七是一套把**小爱音箱变成家庭 AI 语音管家**的系统：保留原厂唤醒与音色的同时，接管"耳朵"和"嘴巴"，接入小智服务端做语音对话、Hermes Agent 做意图与工具调用、Home Assistant 做设备控制。特点：听得懂、会做事、能记住家里的规矩、会主动播报、能放本地音乐、能控电视。

- 上游：fork 自 `idootop/open-xiaoai`（原项目已归档），本 fork 由 Del Wang 等持续维护，**许可证 MIT**。
- 真实运行：单家庭 24×7，客厅小爱 LX06 + 书房蓝牙音箱，共用一套 NAS 服务。

## 二、真实运行架构（三层）

```
小爱音箱（固件 + client-rust/client-patch 补丁）
        │  WebSocket 音频流（:4399 桥接）
        ▼
桥接 xiaoqi-bridge（NAS Docker，host 网络）
        │  ASR / KWS / 唤醒 / 回声消除 / 音乐播放
        ▼
小智服务端 xiaozhi-esp32-server（NAS Docker，:8000 WS / :8003 OTA）
        │  LLM provider = hermes_voice（受限语音入口）
        ▼
Hermes Agent（NAS systemd 原生进程，:8642 网关 / :9119 dashboard）
        │  工具调用（home_mcp.py）
        ├── Home Assistant（:8123）→ 灯 / 空调 / 制冰机 / 电视
        └── 音乐桥（:4400）→ 本地曲库播放
```

**关键事实**：
- Hermes 是 systemd 进程不是 Docker 容器（`docker ps` 查不到）；`HERMES_HOME=/vol1/1000/hermes-state`。
- 小智有完整版 `hermes.py` 和受限版 `hermes_voice.py` 两套 provider；语音走受限版（fail-closed、只控白名单设备）。
- 音乐桥不走 DLNA：音箱侧 `miplayer` 副本 `xqmusic` 从桥接 HTTP（:4400）拉流播放。

## 三、工作区三块内容（开源范围判定）

| 目录 | 体积 | 性质 | 开源处理 |
|---|---|---|---|
| `open-xiaoai-main/open-xiaoai-main/` | 185M | **源码仓库本体**（双层嵌套），含 deploy/examples/packages/docs/promo-video | ✅ 开源主体 |
| `xiaoqi/xiaoqi/` | 227M | NAS 上 `/vol1/1000/xiaoqi` 的运行拷贝：config.py、voice-patch 补丁、models、日志、backup | ⚠️ 只提取脱敏配置样例，模型/日志/backup 不公开 |
| `xiaozhi/xiaozhi/` | 1.1G | 小智服务端运行数据：`.config.yaml`（含真实 key）、mysql 数据+私钥证书、SenseVoiceSmall 模型 893M | ❌ 绝不公开，只提取脱敏配置样例 |

## 四、源码仓库模块地图

### deploy/ — 部署与服务端
| 模块 | 职责 |
|---|---|
| `hermes/` | Hermes Agent 配置、profile（SOUL.md / config.yaml）、MCP 工具集、LLM provider、评测脚本 |
| `hermes/profile/mcp/` | home_rules（场景联动+风险分级）、home_history、tv_control（读屏/按键/开关机）、xiaoqi_music（本地音乐） |
| `xiaozhi/` | 小智服务端部署模板、docker-compose、.env.example |
| `homeassistant/` | HA 配置、设备同步脚本 |
| `sherpa-tts/` | 服务端 TTS 方案与 xiaozhi 覆盖层 |
| `tv-helper/` | 安卓电视控制助手（安装脚本 + shell） |
| `audio-health/` | 音频健康日志与连接恢复 |
| `voice-terminal/` | Windows 语音终端部署 |

### examples/ — 示例与客户端
| 模块 | 职责 |
|---|---|
| `xiaozhi/` | **核心**：小爱→小智桥接（VAD/KWS/唤醒/协议/音乐/原生TTS），含 70+ 测试 |
| `voice-terminal/` | Windows 语音终端（含测试） |
| `kws/` | 唤醒词检测示例 |
| `gemini/`、`migpt/`、`stereo/` | 其他 LLM/TTS 接入示例 |

### packages/ — 固件侧补丁
| 模块 | 职责 |
|---|---|
| `client-rust/` | 小爱音箱 Rust 客户端（音频采集、回声消除、监控、连接），含测试 |
| `client-patch/` | 上游客户端的 shell 补丁（提供 run_shell 通道） |
| `flash-tool/`、`runtime/` | 刷机工具与运行时 |

### 其他
- `docs/`：设计文档、测试记录（唤醒率、延迟、蓝牙音频、音乐等）。
- `promo-video*`/：宣传片生成脚本与成片（3 个 mp4 共 ~176M，开源时可考虑排除以减小仓库体积）。

## 五、开源建议（结构层面）

1. **主体仓库**：只发 `open-xiaoai-main/open-xiaoai-main/` 这一层（去掉双层嵌套外壳），保留上游 MIT LICENSE 与 README。
2. **脱敏配置**：把 `开源准备/` 里的 `config.example.py`、`xiaozhi.config.example.yaml`、`docker-compose.example.yml` 放进仓库的 `docs/examples/` 或 `deploy/` 合适位置。
3. **排除大文件**：`promo-video*/output/*.mp4`（176M）、`owoqrq.tar`（184M）建议不进 git，README 里放截图/外链即可。
4. **不公开**：xiaoqi/ 和 xiaozhi/ 的原始运行数据（模型、日志、mysql、证书、backup）。
