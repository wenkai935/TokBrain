## 二、三个改动的关键设计

### 1. HA 只读（home_mcp）

- 开关：`XIAOQI_HA_VIA_PROXY=1` 才走反代；默认直连，行为与现在完全一致。
- 走反代时 **fail-closed**：取票失败直接抛错，**不回退直连**——否则"认证挂了"会悄悄变成
  "用全能 token 放行"，违背设计初衷。
- 附带治好一个现存 bug：`ha_presence`/`ha_logbook` 依赖 `HA_TOKEN` 环境变量，
  而 gateway 进程环境里没有它（靠 home_mcp 自己 load `agent/.env` 才有）。改走反代后不再依赖它。

### 2. HA 写入（haclient）

- 改动收敛到 `__init__` 和 `_headers()` 两个方法，5 个调用点一行没动。
- 写调用按 domain 映射 scope：light→`ha:light:write`、switch→`ha:switch:write`、
  climate→`ha:climate:write`、notify→`ha:notify:write`、media_player→`ha:media:write`。
- **为什么默认关闭**：灯控/空调/制冰是家里天天用的，现有 `Forbidden` 白名单 + 实体黑名单是有效防线，
  没必要为"认证统一"一次性押上全部设备控制。要切时用 `deploy-batch-a.sh --with-ha-switch`。

### 3. 播报（life-agent）

- **X-Token 保留**，Bearer 票据是新增的第二条路 → 现有 life.py / timer 零改动、零中断。
- 票据要求 `aud=xiaozhi-gateway` + `scope=voice:announce`（`voice:` 前缀映射到 xiaozhi-gateway）。
- 同步 I/O 用 `anyio.to_thread` 跑，不阻塞 FastAPI 事件循环。

## 五、风险与限制（显式列出）

| 风险 | 说明 | 缓解 |
|---|---|---|
| 切 haclient 后灯控全挂 | 反代若不通，所有 HA 写失败 | 默认关闭；`rollback-ha-proxy.sh` 一键退 |
| config.json 未更新导致取票无 scope | 新 scope 不在已部署 config.json 里 | 部署前先更新 config（见上） |
| 播报 401 | 外部调用若既无 X-Token 也无票据 | X-Token 保留，现有调用不受影响 |
| 反代新增 attack surface | 8124 监听 0.0.0.0 | 建议改 127.0.0.1 或防火墙限制到内网 |
| haclient 改动未经真实设备验证 | 只有单测（假 HA） | 切开关后先用 `device_list`（只读）验证，再试单个灯 |
