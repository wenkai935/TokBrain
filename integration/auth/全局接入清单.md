#### 关于电视助手（重要修正）

原清单把电视助手列为"待接批次A"，实测发现：
- Hermes `config.yaml` 的 `mcp_servers` 只有 `home`/`tokbrain`/`pc_control`，**没有 `tv_control`**；
- `tools.py`、`home_mcp.py` 里也没有任何 8765/电视相关调用；
- 电视助手是**电视端 Android App**（Kotlin，`app_process` 运行，端口 8765，静态 `Bearer TOKEN`），
  部署文档写的地址是旧网段的 `192.168.5.9`，当前 NAS 在 `192.168.10.x`。

**结论**：电视控制当前**完全没有接入**，不是"有服务待加鉴权"，而是"要先把 MCP 桥接和 SOUL 路由建起来"。
这属于**新增功能**，应单独立项，不塞进"统一认证后续"，否则会把两件事混在一起、风险叠加。
如要接入，前置是：① 电视与 NAS 同网段可达；② 写 `tv_control` MCP（10 个工具）；③ SOUL 加电视路由规则。届时再按本清单模板加 `tv:` scope。

## 三、明确不纳入（边界，别做无用功）

- **本地 stdio MCP 的启动**：MCP 规范 2026-07-28 明确 stdio「SHOULD NOT follow OAuth，从环境变量取凭据」。4 个 stdio MCP 由 Hermes 拉起，凭据从 env 注入是**合规做法**，不改成票据。
- **语音"认人"**：说话者身份未认证是 fail-closed 证据校验 + 高风险设备硬边界的设计选择，不是缺陷。认证中心只管机器身份。
- **HA 自己的 token 机制**：保留在反代内部，不废除——只是从"散落在各业务 server"收拢到"反代一处持有"。

## 四、接入标准模板（新增服务照抄）

1. **注册 client**：在 `config.example.json` 加一个 client，只给它需要的 aud 和 scope（最小权限）。
2. **生成 secret**：跑 `gen_config.py`，把该 client 的 secret 配到调用方环境变量（不入 git）。
3. **调用方取票**：`from auth_client import AuthClient`；`AuthClient(AUTH_URL, cid, secret, aud=...).auth_header()`。
4. **资源方验票**：
   - HTTP 服务 → `music_auth_guard.check()` 同款中间件（委托 /verify）；
   - HA → 直接走 `ha_proxy`，无需自己验；
   - 其它 → 调 `/verify` + 断言 aud/scope，失败 401。
5. **审计**：每次签发与校验自动落 `audit.jsonl`；资源方额外记"动作/目标"。
6. **回滚**：保留原路径开关（如 `XIAOQI_MUSIC_AUTH_ENABLED=0`），出事能一键退回。

## 五、一票否决的坑

- **别把 HA_TOKEN 下发到业务 server**——反代存在的意义就是让它只活在一处。
- **别用 client 全量 scope 签票**——本版已按 aud 收窄（给音乐桥的票不含 ha:*），别退回全量。
- **别让认证故障变成"放行"**——所有资源方 fail-closed（auth 挂了就拒绝）。
- **别把 secret 写进代码/git**——`gen_config.py` 生成随机值 + chmod 600 + .gitignore。
