# 小七 × TokBrain 整合方案

本目录归档 2026-11-22 ~ 23 的一轮整合工作：把两个原本物理分离的系统收敛成**一个大脑、一个库、两类出口**。

- **小七**：小爱音箱 LX06 + 固件补丁 + Hermes（systemd）+ Home Assistant，负责家居语音
- **TokBrain**：视频知识库（SQLite + 两套 MCP），负责带溯源的问答

两者早已在 **Hermes 这层用 MCP 串起来**，所以"整合"不是重新连线，而是统一身份、收拢规则源、修好工具可见性。

## 为什么放在这个仓库

整合的落点是让 Hermes 同时调用家居工具和知识检索，而 TokBrain 是被整合的知识侧。文档、接口契约、补丁快照放这里，便于和 `mcp_server/` 的实际实现对照。

## 三条核心结论

**1. 规则只能有一个出处。**
知识问答规则写在 MCP 的 `INSTRUCTIONS` 里（`mcp_server/tokbrain_hermes_stdio.py` 只读、`mcp_server/mcp_control.py` 写入），Hermes 加载 MCP 时自动携带。再往 SOUL.md 写一份会造成两个规则源、行为漂移——这条被明确否决。

**2. 身份账本要统一，权限要最小。**
所有服务间调用走 `auth/` 的票据体系：`client_credentials` 换 900 秒 JWT，按 `aud` 收窄 `scope`。知识库也是其中一个 aud（`tokbrain-control`，scope 仅 `kb:read`/`kb:ingest`），与家居权限**双向隔离**：知识库票进不了家居，家居票也进不了知识库。

**3. 工具"存在"不等于"可见"。**
Hermes 会把 MCP 工具放进延迟加载池，池的清单描述塞进桥接提示词里受 token 预算约束。默认预算 4000 装不下实际 5724，导致知识库工具名被截断、模型只会用它看得见的那个（生活知识库 `kb_search`），于是回答了"库里没资料"——**其实是查错了库**。修法是 `tools.tool_search.listing_max_tokens: 8000`。

## ⚠️ 使用注意

- **`patches/` 不是 diff，是完整文件快照**。文件名里的 `.auth-fix` / `.ha-proxy-fix` 表示该版本叠了哪些改造，但基线来自某个具体生产版本，直接用会覆盖掉别处的改动。只作参考实现读。
- **补丁里带家庭内网地址**（`192.168.10.x`），是本方案在真实环境跑通的痕迹，不是可复用配置。
- **`auth/config.example.json` 的 secret 全是 `REPLACE_WITH_RANDOM_SECRET_N` 占位符**，必须用 `gen_config.py` 重新生成随机值，不要手填。
- **部署脚本硬编码了基线文件 md5**，文件一变就主动中止。这是防"拿旧补丁冲掉生产功能"的设计，不是 bug。
- 本分支**不动 master 的业务代码**，master 工作区里的既有改动完全没有被触及。
